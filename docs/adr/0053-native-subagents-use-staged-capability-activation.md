# Native Subagents Use Staged Capability Activation

OpenAIDE first updates its maintained Codex ACP adapter directly to the reviewed upstream v1.7.x release, publishes the fork, and pins that exact package while continuing to omit the native Subagent capability. Product support is then implemented in production code and exercised by deploying it to the OpenAIDE target instance; a separate disposable UI prototype is not required. Native capability advertisement is enabled only after deterministic protocol, persistence, and browser checks pass and a packaged Codex ACP end-to-end smoke test succeeds. The App Server retains an internal, non-user-facing override that can stop advertising native Subagents and return new sessions to the legacy flattened projection if the draft protocol regresses.

This staging separates a low-risk adapter update from activation of a draft protocol and new durable product state. It also gives production-shaped target validation without making native behavior unavoidable during rollback. The pending v1.6.x fork synchronization work is superseded by the direct v1.7.x synchronization rather than released as intermediate OpenAIDE dependencies.
