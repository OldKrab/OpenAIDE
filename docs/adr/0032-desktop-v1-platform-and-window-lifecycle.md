# Desktop v1 Platform and Window Lifecycle

OpenAIDE Desktop v1 supports Windows 11 on x64 and macOS 15 or newer on Apple silicon. Windows ARM64, Intel Macs, and Windows 10 are deferred until OpenAIDE has real-machine validation and CI for those targets; Windows 10 is already outside Microsoft's normal support lifecycle, while multiplying initial CPU targets would multiply packaged App Server binaries, native credential validation, signing, and recovery evidence before the primary desktop paths are proven.

Desktop v1 runs one application process with one main window. A second launch, Dock or taskbar activation, notification click, or future deep link focuses and routes the existing window rather than creating an independent product window. Normal relaunch restores display-clamped window bounds, maximized or fullscreen state, theme, and a durable Task or Settings route, but not pending dialogs, permission requests, secret forms, or unsent Composer state.

macOS exposes standard native application menus and platform shortcuts for New Task, Add or Open Project Folder, Settings, text editing, zoom, window actions, About, and Quit. Windows does not add a persistent macOS-style `File / Edit / View` strip. It integrates one compact app-command entry into the title bar while keeping frequent product actions visible in the shared Project Navigation and contextual actions in their owning surfaces. The Windows title-bar composition must preserve native dragging, caption controls, scaling, accessibility, keyboard access, and snap layouts on real hardware; if that cannot be proven, the command entry falls back to the sidebar header without changing command semantics. Reload and developer tools are development-build commands only.

Window closure follows platform conventions without abandoning active work. Closing the last macOS window keeps the application resident. Closing the last Windows window while work is active offers **Keep running in background**, **Quit and stop**, and **Cancel**; background mode exposes a notification-area icon with **Open OpenAIDE**, **Quit**, and a non-interactive active-work count, but no duplicate Task controls. An idle Windows last-window close exits instead of retaining an unnecessary background process. Explicit Quit on either platform warns when work is active and follows the coherent App Server interruption and shutdown contract in ADR 0022.

Desktop v1 is distributed directly as a notarized macOS DMG and a signed per-user Windows NSIS installer. Windows uses the automatically updated Evergreen WebView2 runtime and includes Microsoft's bootstrapper for a missing or damaged runtime; OpenAIDE does not bundle a fixed browser runtime in v1. MSI, Microsoft Store, Mac App Store, and a fully offline Windows installer remain separate future distribution decisions rather than expanding the initial release matrix.

Desktop v1 does not upload crash reports or telemetry automatically. It records production-safe local native lifecycle events, panic outcomes, WebView-heartbeat failures, App Server generation and shutdown transitions, and stable correlation identifiers without prompts, Chat, paths, URLs, tokens, credentials, or arbitrary error text. Troubleshooting data leaves the machine only through an explicit redacted Support Export action. If real crash tests cannot produce enough local evidence to classify and recover a failure, the candidate desktop framework fails validation.
